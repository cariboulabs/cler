CLER

C++17 DSP flowgraphs for SDRs and embedded systems

Typed channels. Small core. Flowgraph or manual execution.

What it is

CLER is a template-based DSP framework. A block owns its input channels and exposes a procedure() method. Its output channels are passed to that method, so connections are checked by the compiler.

The same block can run in a threaded flowgraph or in a loop you control. The core is header-only and does not need exceptions.

Project status: CLER is in early development. Block names and APIs can change.

Main parts

Typed channels

Static or heap-backed SPSC queues. Batch and zero-copy access are built in.

Three schedulers

One thread per block, a fixed worker pool, or block islands. Affinity is available on Linux.

Desktop and embedded

Linux and macOS, plus task policies for FreeRTOS, ThreadX, and Zephyr. Bare metal uses manual execution.

Desktop blocks

Sources, sinks, SDR drivers, plots, filters, resamplers, channelizers, UDP, and audio.

A desktop-block example

This example generates two tones, adds them, limits the rate, and plots the result. It uses the optional GUI build.

#include "cler.hpp"
#include "task_policies/cler_desktop_tpolicy.hpp"
#include "desktop_blocks/gui/gui_manager.hpp"
#include "desktop_blocks/math/add.hpp"
#include "desktop_blocks/plots/plot_timeseries.hpp"
#include "desktop_blocks/sources/source_cw.hpp"
#include "desktop_blocks/utils/throttle.hpp"
#include <chrono>
#include <thread>

int main() {
    constexpr size_t sample_rate = 1000;

    cler::GuiManager gui(800, 400, "CLER");
    SourceCWBlock<float> tone_a("Tone A", 1.0f, 1.0f, sample_rate);
    SourceCWBlock<float> tone_b("Tone B", 1.0f, 20.0f, sample_rate);
    AddBlock<float, 2> add("Add");
    ThrottleBlock<float> throttle("Throttle", sample_rate);
    PlotTimeSeriesBlock plot("Plot", {"Sum"}, sample_rate, 3.0f);

    auto graph = cler::make_desktop_flowgraph(
        cler::BlockRunner(&tone_a, &add.in[0]),
        cler::BlockRunner(&tone_b, &add.in[1]),
        cler::BlockRunner(&add, &throttle.in),
        cler::BlockRunner(&throttle, &plot.in[0]),
        cler::BlockRunner(&plot)
    );

    graph.run();
    while (!gui.should_close()) {
        gui.begin_frame();
        plot.render();
        gui.end_frame();
        std::this_thread::sleep_for(std::chrono::milliseconds(20));
    }
    graph.stop();
}

A BlockRunner takes a block first, then the downstream channels that receive its outputs.

First build: core examples

You need CMake 3.16 or newer, a C++17 compiler, threads, and pkg-config. This path skips GUI and liquid-dsp.

git clone https://github.com/cariboulabs/cler.git
cd cler
mkdir build-core
cd build-core
cmake -DCLER_BUILD_BLOCKS_GUI=OFF -DCLER_BUILD_BLOCKS_LIQUID=OFF ..
make -j4
./desktop_examples/flowgraph

GUI example

The default build requires OpenGL and X11 on Linux. It uses system GLFW when present and otherwise fetches it. ImGui, ImPlot, and liquid-dsp are fetched while their blocks are enabled.

mkdir build
cd build
cmake ..
make -j4
./desktop_examples/hello_world
